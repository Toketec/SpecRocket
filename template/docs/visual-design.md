# {项目名} — 视觉设计规范

> **负责人**: PM / 设计师
> **定位**: **全局独一份、一般不会修改、与版本无关**的视觉审美边界文件。
> **用途**: 确定产品及衍生客户端的视觉审美边界（颜色、大小、设计语言、风格、动效、间隔等），供所有版本与所有客户端复用。
> **与原型/图表的关系**: 随版本变动的具体 UI 形态（页面结构、布局、内容、框线图、文字说明）由 `sprints/*/docs/prototypes/prototypes.md`（UI 设计文档）+ `prototype.html`（可交互原型）承载；系统层图表（用例/ER/架构）见 `uml-pack.md`。**本文档只定义视觉层，不定义具体形态。**
> **必填规则**: 即使项目无前端界面（纯后端/脚本/CLI），也**必须保留此文件**。无实质内容时写一行占位说明为什么不需要，不可遗漏或删除。

## 🚫 边界声明（硬性约束，违反视为规范违规）

**本文档禁止出现任何业务相关设计。** 判断标准：一段内容离开了「具体某个业务/页面」就无法理解 → 它就是业务设计，必须放进 `sprints/sp-NNN-*/docs/prototypes/prototypes.md`。

| ❌ 禁止（业务形态，进 sprint prototypes/） | ✅ 允许（审美边界，本文件） |
|:----|:----|
| 具体页面结构、页面清单、布局 | 颜色 token、色板 |
| 具体元素（导航栏、卡片、弹窗在哪个页面出现） | 字体层级、字号、字重、行高 |
| 页面内容、文案、业务字段 | 间距栅格、内容最大宽度、圆角、阴影层级 |
| 框线图、页面线框、布局示意 | 动效时长、缓动曲线、过渡风格 |
| 业务流程图、用户旅程 | 设计语言（极简/圆润/科技感…）、风格关键词 |
| 某页面用某组件、页面状态内容 | 组件设计规范（跨版本稳定的视觉属性：圆角/颜色/状态色） |
