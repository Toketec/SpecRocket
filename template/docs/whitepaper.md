## 📌 写作质量标准（必读，不满足视为未完成）

白皮书是产品的对外门面，**禁止敷衍**。编写时必须满足：

| # | 标准 | 要求 |
|:-:|:----|:----|
| 1 | 🎯 **全盘视野** | 站在产品完整生命周期看问题（市场 → 用户 → 方案 → 价值 → 商机 → 路径），不聚焦某个版本功能 |
| 2 | 🚫 **无版本关联性** | 不写具体版本功能清单（版本功能进 `sprints/`）；路线图只写阶段方向与里程碑，不写功能细节 |
| 3 | 👤 **产品专家视角** | 讲清问题本质、行业现状、为什么现有方案不行 |
| 4 | 💼 **商业精英视角** | 讲透「痛点 → 收益 → 商机」闭环：解决什么痛点、用户/客户获得什么收益、市场机会在哪里 |
| 5 | 💎 **价值显性化** | 每个价值点必须给出证据/指标或可感知的具体收益，不写空话 |
| 6 | 🧠 **低认知门槛** | 结构先问题后方案、段落短、用词通俗（专有名词附解释）、核心内容一屏可读完、能激发读者使用与投入 |

> **验收判断**: 把白皮书给一个不了解本项目的人读，TA 能否在 3 分钟内回答「这产品解决什么问题、凭什么值得用/值得投」。答不出 = 重写。
>
> **占位例外**: 仅内部工具/脚本可写一行占位（`本项目为内部工具，不涉及对外白皮书。`）；**对外产品一律按上述标准写完整**，不得敷衍。
